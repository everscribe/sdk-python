# v0.2.0

Delivery retries for `BufferedRecorder`. Events are no longer dropped on the first failed flush. It pairs with an Everscribe ingest fix that returns 503 (not 401) when an API key lookup fails for reasons other than not-found. Until that fix is live, a batch rejected with 401 during a database outage is reported to `on_drop` as `REJECTED` instead of retried.

## New

- `initial_backoff`: base wait in seconds before the first retry. Default `0.5`.
- `max_backoff`: cap in seconds on a single wait between retries. Default `30.0`.
- `max_retry_duration`: how long in seconds one batch is retried before its events are dropped. Default `300.0`.
- `None`, `<= 0` or NaN on any of the three uses the default. Huge values are clamped.
- `on_drop(events, reason, err)`: callback for every discarded event batch, with a `DropReason` and an error: the last delivery error for `REJECTED` and `RETRIES_EXHAUSTED`; for a `BUFFER_FULL` drop from the middleware's own record, `BufferFullError` under `OverflowPolicy.ERROR` and a `TimeoutError` (the 15 s wait) under `OverflowPolicy.BLOCK`; and `None` otherwise. The callback must not block or call `record`, `flush` or `close` on the same recorder, and may run concurrently on request threads and the worker. An `Exception` it raises is caught and logged. A `BaseException` raised on the worker thread stops the worker, can leave the rest of that batch unreported, and later records are reported as `CLOSED`.
- `DropReason`: `BUFFER_FULL`, `REJECTED`, `RETRIES_EXHAUSTED`, `SHUTDOWN`, `CLOSED`. It is a `str` enum, so `reason.value` gives the lowercase name for metric labels.
- `stats().retries`: total delivery retries.
- `stats().dropped_by_reason`: a `DroppedByReason` with events dropped per reason.
- `NetworkError`: raised by `HTTPRecorder` when the transport fails before a response (an `OSError` or `http.client.HTTPException`). Always transient; the original exception is on `__cause__`.
- `EncodeError`: raised by `HTTPRecorder` when an event cannot be serialized to JSON. Nothing is sent.
- `HTTPError.retry_after`: the server's `Retry-After` in seconds, `0.0` if absent or not a whole number of seconds. Honored by the retry loop up to `max_backoff`.
- `everscribe.event.is_auto_recording(e)`: for `Recorder` implementers, says whether the middleware is recording `e` and has no caller to return an error to.
- The `BatchRecorder` protocol's `record_batch` takes an optional `timeout` keyword (the per-attempt `flush_timeout`). Recorders without the parameter still work and are called without it.
- A recorder `Transport` may return `(status, body, headers)` as well as `(status, body)`. The headers feed `retry_after`. The minter's `Transport` is a separate type and still returns `(status, body)`.

## Behavior changes

- Failed sends are retried with jittered exponential backoff (honoring `Retry-After`) instead of dropped. `NetworkError`, `TimeoutError`, 429, 5xx, and any error with a truthy `transient` attribute or `transient()` method are retried. After `max_retry_duration` the batch is dropped as `RETRIES_EXHAUSTED`.
- A multi-event batch rejected with 400, 409 or 413, or one that fails with `EncodeError`, is split in half to isolate the bad events, up to 32 sends per batch. Events that cannot be delivered, and batches failing with any other error, are dropped as `REJECTED`. A NaN in metadata is written by `json.dumps` and rejected by the server with a 400, so it splits too.
- `stats().flush_errs` now counts failed delivery attempts, so one flush can add several. `stats().dropped` counts only `BUFFER_FULL` drops.
- `flush(timeout)` no longer raises the inner recorder's error. It returns once the events queued at the call are delivered or reported to `on_drop`, or raises `TimeoutError` if `timeout` elapses first. It never cancels a send.
- `flush()` and the `close()` drain now send in batches of up to `flush_size`. v0.1.0 sent the whole queue in one request.
- Every send is capped at `flush_size`, and batches go back to back only while a full batch is queued, a `flush()` is waiting, or `close()` is draining. Otherwise each `flush_interval` tick sends one batch and the remainder waits for the next tick. v0.1.0 sent the whole queue in one request on the size threshold and on each tick.
- `flush()` returns at once, without delivering anything, after `close()` or once the worker has stopped.
- `close()` drains with retries for up to `drain_timeout`, then stops retries, waits up to 1 s more, reports what is still queued as `SHUTDOWN`, and raises `DrainTimeoutError`. A running inner call can't be interrupted, so its in-flight batch is reported when that call returns, which can be after `close()` has returned. `close()` can therefore take up to `drain_timeout` plus 1 s.
- Later and concurrent `close()` calls wait for the first and get the same outcome, including its `DrainTimeoutError`. v0.1.0 returned at once on a second call. A `close()` interrupted by an exception such as `KeyboardInterrupt` can be retried.
- `flush_size` and `flush_interval` of `None`, `<= 0` or NaN now use the defaults of 100 and 5.0.
- `record()` after `close()`, or once the worker has stopped, and `BLOCK` waiters released by `close()`, are reported as `CLOSED`. v0.1.0 dropped them silently.
- The middleware's auto-record (`end_event`) gives up after 15 s under `BLOCK`. That event, and one an `ERROR`-policy recorder refuses during auto-record, is reported to `on_drop` as `BUFFER_FULL`.
- `HTTPRecorder` used directly now raises `NetworkError` and `EncodeError` instead of raw `urllib` and `json` errors. A transport that raises `urllib.error.HTTPError` surfaces as everscribe's `HTTPError`.
- `BufferedStats` gained fields (`retries`, `dropped_by_reason`), so hand-built instances need them.
- `record()` stores a shallow copy of the event, and retries keep it queued longer than before. Don't mutate a recorded event's `actor`, `target` or `metadata`.
- The worker is a daemon thread. Always call `close()` before the process exits, or what is still buffered is lost without an `on_drop` report.
